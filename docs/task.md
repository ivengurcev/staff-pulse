# Staff Pulse — базовое тестовое задание

> Источник: присланный PDF `staff_pulse_assignment.pdf`.
> Здесь только содержание исходного задания, без наших архитектурных дополнений.

## Общая информация

Frontend · React · TypeScript

Дедлайн: 2–3 дня.

## Задача

Реализовать дашборд для мониторинга орг-структуры компании.

Структура иерархическая:

```text
дивизионы
    → отделы
        → команды
```

У каждого узла:

- численность сотрудников;
- бюджет;
- метрика эффективности.

Нужен интерактивный просмотр дерева и аналитическая таблица с агрегированными показателями.

## Стек

- React
- Vite
- TypeScript

Будет плюсом:

- styled-components для стилизации.

## Нефункциональные требования

### Надёжность

- обработка состояний загрузки;
- обработка ошибки;
- обработка пустого ответа;
- корректная отмена запросов при размонтировании компонента.

### Эффективность обращения к API

- кэширование ответов;
- избегание лишних запросов;
- stale-while-revalidate или аналог;
- инвалидация кэша только при реальном изменении данных.

## Mock API

Реализовать собственный сервер.

### GET /api/org-tree

Возвращает плоский массив объектов:

```ts
{
    id,
    name,
    parentId,
    headcount,
    budget,
    performance,
    updatedAt
}
```

Требования:

- минимум 40 узлов;
- не менее трёх уровней вложенности.

## 01 FOUNDATION

Проект, API, дерево.

- Scaffold: Vite + React + TypeScript.
- Абсолютные импорты.
- Схема API-ответа валидируется на клиенте.
- Невалидный ответ считается ошибкой.
- Запрос через слой кэширования.
- Stale time — 5 секунд.
- Интерактивное дерево.
- Раскрытие/скрытие ветвей.
- Второй уровень открыт по умолчанию.
- Каждый узел показывает:
    - `name`;
    - `headcount`;
    - цветовой индикатор `performance`.
- Состояния:
    - loading;
    - error;
    - empty response.
- Никакого inline CSS.

---

## 02 CORE

Аналитическая таблица.

- Переключатель «Дерево / Таблица» или split-view при ширине ≥1280 px.
- Столбцы:
    - Подразделение;
    - Уровень;
    - Всего сотрудников;
    - Бюджет суммарный;
    - Средняя эффективность.
- Суммарные показатели включают данные узла и всех его потомков.
- Средняя эффективность — взвешенная по `headcount`.
- Сортировка по любому столбцу.
- Двойной клик — обратная сортировка.
- Фильтр по названию:
    - real-time;
    - debounce 250 мс.
- Клик по строке выделяет узел в дереве.
- Бюджеты отображаются в формате `12 345 678 руб.`.
- Агрегация считается один раз после загрузки данных и мемоизируется.

---

## 03 POLISH

Live-обновления и UX.

- Сервер поддерживает обновления в реальном времени.
- Клиент реализует один из вариантов:
    - WebSocket;
    - SSE;
    - эффективный polling.
- Нужно учитывать:
    - частоту изменений;
    - backoff;
    - минимизацию лишних запросов.
- Клиент применяет патч без полного refetch.
- Обновлённые ячейки получают fade-out примерно 1.5 секунды.
- Пересчёт агрегатов только для затронутого узла и его предков.
- Индикатор соединения в шапке.
- Экспоненциальный backoff при обрыве.
- Keyboard navigation по таблице:
    - стрелки;
    - Home/End;
    - Enter.
- Анимация раскрытия дерева через height transition.
- Учитывать `prefers-reduced-motion`.

## 04 BONUS

Production + AI-фича.

- Docker:
    - `docker-compose up` поднимает клиент и сервер;
    - конфигурация через `.env`.
- Nginx:
    - проксирует API;
    - отдаёт статику с gzip.
- Production-сборка ≤200 КБ gzip.
- AI-поиск:
    - строка поиска принимает естественный язык;
    - ответ преобразуется в структурированный фильтр на клиенте;
    - fallback — текстовый поиск.
