# Staff Pulse — step/2 CORE

## Задача

Реализовать только `02 CORE` — аналитическую таблицу с агрегированными показателями поверх уже существующего интерактивного дерева FOUNDATION.

Не переходить к требованиям POLISH и BONUS.

## Требования

### Представление

- Переключатель «Дерево / Таблица» или split-view при ширине ≥1280 px.
- Существующее интерактивное дерево FOUNDATION сохраняется.

### Таблица

Столбцы:

- Подразделение;
- Уровень;
- Всего сотрудников;
- Бюджет суммарный;
- Средняя эффективность.

### Агрегаты

- Суммарные показатели включают данные узла и всех его потомков.
- Средняя эффективность — взвешенная по `headcount`.
- Уровень узла отображается в столбце «Уровень».
- Агрегация считается один раз после загрузки данных и мемоизируется.

### Сортировка

- Сортировка по любому столбцу.
- Двойной клик — обратная сортировка.

### Фильтр

- Фильтр по названию.
- Real-time.
- Debounce 250 мс.
- Единственный search находится в шапке и фильтрует только таблицу.

### Связь таблицы и дерева

- Клик по строке выделяет узел в дереве и раскрывает его предков.
- Клик по узлу дерева выделяет соответствующую строку таблицы.
- Chevron управляет только раскрытием/сворачиванием.

### Форматирование

- Бюджеты отображаются в формате `12 345 678 руб.`.

### Тесты

- Unit-тест функции агрегации.

## Что не делать на step/2

Не реализовывать:

- realtime transport (SSE / WebSocket / polling);
- patch без полного refetch;
- подсветку обновившихся ячеек;
- частичный пересчёт агрегатов;
- connection indicator;
- exponential backoff;
- keyboard navigation таблицы;
- анимацию дерева (height transition);
- `prefers-reduced-motion`;
- Docker / docker-compose / `.env`;
- Nginx / gzip;
- ограничение production bundle ≤200 КБ gzip;
- AI-поиск.

## Проверка

Обязательные результаты:

- аналитическая таблица;
- агрегированные `headcount` и `budget`;
- взвешенный `performance`;
- уровень узла;
- сортировка и обратная сортировка;
- realtime-фильтр с debounce 250 мс;
- выбор строки синхронизирован с деревом;
- форматирование бюджета;
- агрегация вычисляется один раз после загрузки и мемоизируется;
- unit-тест функции агрегации.

Полный перечень автоматических и ручных проверок зафиксирован в `docs/plans/02-core.md` (Task 5).

Ручное ревью и все проверки пройдены; `step/2` завершён и тегирован (`step/2`).
