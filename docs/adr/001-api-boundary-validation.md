# ADR 001: Двухэтапная валидация API boundary

## Контекст

TypeScript-типы не проверяют данные, полученные по HTTP. Проверки формы отдельных объектов также недостаточно: массив может содержать корректные поля, но битую иерархию — повторяющиеся ID, отсутствующего родителя или цикл.

## Решение

Client проверяет ответ последовательно:

1. Zod валидирует массив и форму каждого `OrgNode`.
2. `validateOrgTree()` проверяет целостность связей между узлами.

Любая ошибка завершает TanStack Query с ошибкой и переводит UI в единый error-state. Server и client сохраняют собственные типы по разные стороны HTTP boundary.

## Альтернативы

- Доверять общему TypeScript-типу client/server — отклонено, потому что тип исчезает в runtime и создаёт ложную гарантию на сетевой границе.
- Использовать только Zod-схему объектов — отклонено, потому что она не гарантирует корректность графа целиком.
- Передавать вложенное дерево — отклонено, потому что контракт задания требует плоский массив.

## Последствия

- UI получает только данные с корректной формой и иерархией.
- Проверки формы и domain-инвариантов можно тестировать независимо.
- Валидация требует дополнительного линейного прохода и `O(n)` памяти.
- Ошибки boundary не раскрывают пользователю внутренние диагностические сообщения.
