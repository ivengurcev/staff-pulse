# Codex — контекст работы

Перед реализацией конкретного шага читать:

1. `docs/task.md` — исходное тестовое задание целиком.
2. `docs/steps.md` — границы этапов.
3. `docs/decisions.md` — уже принятые технические решения.
4. `docs/clarifications.md` — трактовки неоднозначных требований.
5. Файл текущего шага в `docs/steps/`.

## Общие правила

- Сначала изучить существующий репозиторий.
- Не пересоздавать уже работающую структуру.
- Не реализовывать будущие этапы заранее.
- Не обновлять major-версии зависимостей без причины.
- Не создавать git commit/tag без отдельной команды.
- Не придумывать требования, которых нет в `docs/task.md` или файлах уточнений.
- Если найдено противоречие между файлами, сообщить о нём до реализации.
- После изменений выполнить доступные проверки и сообщить фактический результат.
